## 1. High-Level Overview

DeepParameters is organised around one central function:

```python
from deepparameters import learn_cpd_for_node
```

This single function is the **entire public API** for learning one node's CPD. Everything else — architectures, samplers, parallel runners — is wired together behind this interface.

For learning an entire network at once, there is:

```python
from deepparameters import learn_network_parameters_parallel
```

The package lives in the `deepparameters_package/deepparameters/` directory and is published to PyPI as `deepparameters`.

## 3. Package Modules

### `__init__.py` — The Front Door

This file defines what users see when they `import deepparameters`. It:

- Sets `__version__ = "2.0.9"`, `__author__`, `__email__`, `__license__`
- Imports and re-exports `learn_cpd_for_node`, `DeepParametersLearner`
- Imports utility functions: `compare_cpds`, `print_comparison_metrics`, `visualize_cpd`
- Tries to import parallel functions; if `parallel.py` fails it sets `PARALLEL_AVAILABLE = False` gracefully
- Exposes `__all__` so that `from deepparameters import *` gives a clean API

```python
# What gets exported
__all__ = [
    'learn_cpd_for_node',
    'DeepParametersLearner',
    'compare_cpds',
    'evaluate_cpd_performance',   # alias for compare_cpds
    'print_comparison_metrics',
    'visualize_cpd',
    # + parallel functions if available
]
```

---

### `core.py` — The Orchestrator

This is the most important file for users. It contains:

#### `learn_cpd_for_node(node, data, true_model, learnt_bn_structure, num_parameters, ...)`

The main function. It:
1. Validates inputs via `validate_inputs()`
2. Calls `_get_network_learner()` to instantiate the right architecture class
3. Calls `get_sampler()` to instantiate the right sampling class
4. Calls `learner.fit(data)` — trains the neural network
5. Calls `learner.get_cpd()` — builds the CPD table by querying the neural network
6. Calls `sampler.refine_cpd(cpd, data, node, model)` — refines via statistical method
7. Returns the final `TabularCPD` object

**Parameters:**

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `node` | str | required | Name of the node whose CPD to learn |
| `data` | DataFrame | required | Training data (must be discrete integers) |
| `true_model` | BayesianNetwork | required | The true network (used for evaluation) |
| `learnt_bn_structure` | BayesianNetwork | required | The learned structure |
| `num_parameters` | int | required | Neural network size parameter |
| `network_type` | str | `'simple'` | Architecture choice |
| `sampling_method` | str | `'1'` | Refinement method choice |
| `epochs` | int | `100` | Training epochs |
| `batch_size` | int | `32` | Mini-batch size |
| `learning_rate` | float | `0.001` | Adam learning rate |
| `validation_split` | float | `0.2` | Fraction held out for validation |
| `early_stopping` | bool | `True` | Stop early if validation loss stops improving |
| `optimizer` | str | `'adam'` | Optimizer: `'adam'`, `'adamw'`, `'sgd'`, `'rmsprop'` |
| `early_stopping_patience` | int | `10` | Epochs with no improvement before stopping |
| `verbose` | bool | `False` | Print detailed progress |
| `random_state` | int | `42` | Seed for reproducibility |

#### `_get_network_learner()` — Factory Function

Maps `network_type` strings to architecture classes:

```python
network_learners = {
    'simple':           SimpleCPDLearner,
    'advanced':         AdvancedCPDLearner,
    'ultra':            UltraCPDLearner,
    'mega':             MegaCPDLearner,
    'lstm':             LSTMCPDLearner,
    'bnn':              BayesianNeuralNetworkCPDLearner,
    'vae':              VAECPDLearner,
    'autoencoder':      AutoencoderCPDLearner,
    'normalizing_flow': NormalizingFlowCPDLearner,
}
```

#### `list_available_architectures()` and `list_available_sampling_methods()`

Utility functions that print human-readable lists of all options.

### `architectures.py` — The Neural Brains

Contains all 9 neural network architecture implementations. Each extends `BaseCPDLearner`.

#### `BaseCPDLearner` (Abstract Base Class)

All architectures inherit from this. It handles:

- **`__init__`:** Stores `node`, `data`, `true_model`, `learnt_bn_structure`, `num_parameters`, plus all training hyperparameters. Sets random seeds.
- **`_prepare_data()`:** Extracts parent nodes from the network structure, builds `X` (parent values) and `y` (node values) arrays. Computes `node_card` (how many states the node has) and `parent_cards`.
- **`_get_optimizer()`:** Creates an optimizer object from a string ('adam', 'adamw', 'sgd', 'rmsprop', 'nadam'). For sklearn fallback, maps to solver strings.
- **`get_cpd()`:** The shared CPD-construction logic. For every combination of parent states, gets the neural network's prediction, reshapes it into a CPD matrix, normalises columns to sum to 1, and returns a `TabularCPD`.
- **`_build_model()` (abstract):** Subclasses define the network structure here.
- **`fit(data)` (abstract):** Subclasses define training here.

## 4. The 9 Neural Network Architectures

### Architecture Comparison Table

| Key | Class | Backend Preferred | Architecture | Best For |
|-----|-------|-------------------|--------------|----------|
| `'simple'` | `SimpleCPDLearner` | sklearn MLP | 2-layer MLP (64, 32) | Fast baseline, most compatible |
| `'advanced'` | `AdvancedCPDLearner` | sklearn MLP | 3-layer MLP (128, 64, 32) | Better accuracy, still fast |
| `'ultra'` | `UltraCPDLearner` | sklearn MLP | 4-layer MLP (256, 128, 64, 32) | Higher accuracy, slower |
| `'mega'` | `MegaCPDLearner` | sklearn MLP | 5-layer MLP (512, 256, 128, 64, 32) | Maximum capacity |
| `'lstm'` | `LSTMCPDLearner` | TensorFlow* | LSTM (64) → LSTM (32) → Dense | Sequential/temporal relationships |
| `'bnn'` | `BayesianNeuralNetworkCPDLearner` | TensorFlow* | Dense + MC Dropout for uncertainty | Uncertainty quantification |
| `'vae'` | `VAECPDLearner` | TensorFlow* | Encoder-latent space-Decoder | Generative modelling of CPD space |
| `'autoencoder'` | `AutoencoderCPDLearner` | TensorFlow* | Encoder → bottleneck → Decoder | Dimensionality reduction |
| `'normalizing_flow'` | `NormalizingFlowCPDLearner` | TensorFlow* | Affine coupling layers | Exact density estimation |

*Falls back to sklearn when TensorFlow is not installed.

---

### `SimpleCPDLearner` (and Advanced, Ultra, Mega)

The simplest architecture. Uses `sklearn.neural_network.MLPClassifier` (for binary nodes) or `MLPRegressor` (for multi-class nodes).

```
Input: [parent_1_value, parent_2_value, ...]
         ↓
Dense(64) + ReLU
         ↓
Dense(32) + ReLU
         ↓
Output: [P(node=0), P(node=1), ...]  (softmax)
```

`AdvancedCPDLearner`, `UltraCPDLearner`, and `MegaCPDLearner` extend `SimpleCPDLearner` with progressively wider/deeper networks. When TensorFlow is available, these can use deeper TF architectures; otherwise they use correspondingly larger sklearn MLPs.

---

### `LSTMCPDLearner`

Uses a Long Short-Term Memory recurrent network. Data is reshaped to `(batch, 1, num_parents)` — treating each parent combination as a single-step sequence. This allows the LSTM to potentially discover ordering/sequential relationships.

```
Input: (batch, 1, num_parents)
         ↓
LSTM(64, dropout=0.2, return_sequences=True)
         ↓
LSTM(32, dropout=0.2)
         ↓
Dense(64, ReLU) + Dropout(0.3)
         ↓
Dense(32, ReLU) + Dropout(0.2)
         ↓
Output: softmax / sigmoid
```

**Practical note:** Because CPD inputs are not truly sequential (parent values are just feature vectors), the LSTM's advantage over a plain MLP here is dataset-dependent. It tends to be most useful when parent variables have a natural ordering.

---

### `BayesianNeuralNetworkCPDLearner`

Uses Monte Carlo Dropout to estimate **uncertainty** in the CPD probabilities.

```
Input
  ↓
Dense(128, ReLU) + Dropout(0.2)  ← dropout stays ON at inference time
  ↓
Dense(64, ReLU) + Dropout(0.2)
  ↓
Dense(32, ReLU) + Dropout(0.1)
  ↓
Output (softmax)
```

At inference time, multiple forward passes are run with dropout active. The mean gives the probability estimate; the standard deviation gives uncertainty. This produces **uncertainty-aware CPDs** — not just a point estimate but a sense of how confident the network is.

---

### `VAECPDLearner` (Variational Autoencoder)

A generative approach. The VAE learns a compressed latent representation of the input and reconstructs probabilities from it.

```
Input: parent values
    ↓
Encoder: Dense(64) → Dense(32)
    ↓
Latent: mean (μ) and log-variance (log σ²) vectors (dim=16)
    ↓
Reparameterisation: z = μ + σ × ε  where ε ~ N(0,1)
    ↓
Decoder: Dense(32) → Dense(64)
    ↓
CPD Output: Dense(node_card, softmax)
Also outputs: Reconstruction (for loss)
```

The VAE loss = reconstruction loss + KL divergence loss (forces the latent space to be smooth and Gaussian-like). This gives better generalisation when parent combinations are sparse.

---

### `AutoencoderCPDLearner`

A standard (non-variational) autoencoder. Learns a compressed representation of the parent-node relationship.

```
Input
    ↓
Encoder: Dense(64, ReLU) → Dense(32, ReLU) → Dense(16, ReLU)  [bottleneck]
    ↓
Decoder: Dense(32, ReLU) → Dense(64, ReLU) → Dense(node_card, softmax)
```

The bottleneck forces the network to learn the most essential features. Unlike VAE, no probabilistic constraint is placed on the latent space.

---

### `NormalizingFlowCPDLearner`

Uses affine coupling layers to model complex probability distributions exactly (without approximation).

```
Input
  ↓
Affine Coupling Layer 1:
  half the dimensions pass through unchanged,
  the other half are scaled and shifted by a sub-network
  ↓
Affine Coupling Layer 2: (similar, different dimensions masked)
  ↓
Output: transformed distribution → CPD probabilities
```

Normalising flows are theoretically more expressive than VAEs (exact log-likelihood, invertible transformations) but more complex to implement and tune.

## 5. The 12 Sampling / Refinement Methods Summary

See [01_theory_and_concepts.md](01_theory_and_concepts.md) for full explanations. Quick reference:

| # | `sampling_method=` | Class | Speed | Accuracy |
|---|-------------------|-------|-------|----------|
| 1 | `'1'` | `GibbsSampler` | Slow | High (MCMC) |
| 2 | `'2'` | `MetropolisHastingsSampler` | Slow-Medium | High |
| 3 | `'3'` | `ImportanceSampler` | Medium | Good |
| 4 | `'4'` | `BayesianParameterEstimator` | Fast | Very Good |
| 5 | `'5'` | `VariationalInferenceSampler` | Medium | Good |
| 6 | `'6'` | `HamiltonianMonteCarlo` | Slow | Very High |
| 7 | `'7'` | `SequentialMonteCarlo` | Slow | High |
| 8 | `'8'` | `AdaptiveKDESampler` | Medium | Good |
| 9 | `'9'` | `WeightedSampler` | Very Fast | Baseline |
| 10 | `'10'` | `StratifiedSampler` | Fast | Good |
| 11 | `'11'` | `KDESampler` | Medium | Good |
| 12 | `'12'` | `DirichletBayesianSampler` | Medium | Very Good |

All samplers extend `BaseSampler` and implement `refine_cpd(cpd, data, node, model) → TabularCPD`.

All samplers have a fallback: if the refinement fails for any reason, they return the original neural network CPD unchanged.

## 6. The Parallel Engine

### `parallel.py` — Key Classes

#### `FactorGroup`

A simple container representing a group of nodes that can be learned together:
- `nodes`: list of node names
- `group_id`: integer ID
- `estimated_complexity`: based on number of nodes
- `learned_cpds`: dict filled after learning completes

#### `ParallelLearningProgress`

A thread-safe progress tracker (uses `threading.Lock`):
- Counts completed groups and nodes
- Provides estimated remaining time
- Callback-friendly for monitoring

#### `ParallelCPDLearner`

The main parallel learning class.

**`learn_network_parameters(data, true_model, learnt_bn_structure, ...)`**

1. **Decomposes the network** into `FactorGroup`s using either `_topological_decomposition()` or `_parent_child_decomposition()`.
2. **Creates a thread pool** (`ThreadPoolExecutor` with `max_workers` threads). Using threads (not processes) because the GIL is released during heavy numpy/tensorflow computation, and threads share memory more efficiently here.
3. **Submits each group** to the pool. The group's nodes are learned sequentially within the group but groups run in parallel.
4. **Collects results** using `as_completed()` as each group finishes.
5. **Returns** a dict of `{node_name: TabularCPD}`.

**`_topological_decomposition(network)`**

Uses `networkx.topological_sort()` to assign a "depth" to each node. Nodes at the same depth form one group. Guarantees parents are always in earlier groups than children.

**`_parent_child_decomposition(network)`**

Groups each parent with its children. Independent branches of the network become separate groups, allowing them to be learned simultaneously.

#### `learn_network_parameters_parallel()` (Module-level function)

A convenience wrapper around `ParallelCPDLearner` with sensible defaults — the easiest entry point for parallel learning:

```python
from deepparameters import learn_network_parameters_parallel

cpds = learn_network_parameters_parallel(
    data=data,
    true_model=true_model,
    learnt_bn_structure=bn,
    network_type='simple',
    sampling_method='4',
    parallel_style='topological'
)
```

#### `ParallelLearningBenchmark`

A benchmarking class for comparing sequential vs parallel performance across multiple network topologies and worker counts. Used by the experiment scripts in the root workspace.

## 7. Data Flow Diagram

```
User Code
    │
    │  learn_cpd_for_node('Disease', data, true_model, learnt_model,
    │                      num_parameters=10, network_type='simple',
    │                      sampling_method='4')
    │
    ▼
core.py: validate_inputs()
    │
    ├─► architectures.py: SimpleCPDLearner.__init__()
    │       │  _prepare_data()
    │       │    → parents = ['Fever', 'Cough']
    │       │    → X = data[['Fever','Cough']].values  shape (500, 2)
    │       │    → y = data['Disease'].values           shape (500,)
    │       │    → node_card = 2
    │       │    → parent_cards = [2, 2]
    │       │
    │       ├─► _build_model()
    │       │    → MLPClassifier(hidden_layer_sizes=(64, 32), ...)
    │       │
    │       └─► fit(data)
    │            → model.fit(X, y)
    │            → is_fitted = True
    │
    ├─► architectures.py: SimpleCPDLearner.get_cpd()
    │       │  Generate all parent combos: [[0,0],[0,1],[1,0],[1,1]]
    │       │  → predictions = model.predict_proba([[0,0],[0,1],[1,0],[1,1]])
    │       │  → cpd_values shape (2, 4)
    │       │  → normalise columns
    │       │  → TabularCPD('Disease', 2, cpd_values,
    │       │               evidence=['Fever','Cough'], evidence_card=[2,2])
    │
    ├─► sampling.py: BayesianParameterEstimator.refine_cpd()
    │       │  count data occurrences per parent config
    │       │  add Dirichlet prior α=1.0
    │       │  normalise
    │       │  → refined TabularCPD
    │
    └─► Return refined TabularCPD to user
```

## 11. TensorFlow vs Sklearn Fallback

DeepParameters is designed to work **with or without TensorFlow**. This is handled gracefully throughout.

### How the Fallback Works

At the top of `architectures.py`:

```python
HAS_TENSORFLOW = False
try:
    import tensorflow as tf
    HAS_TENSORFLOW = True
except ImportError:
    tf = None
```

Each architecture's `_build_model()` checks `HAS_TENSORFLOW`:

```python
def _build_model(self):
    if not HAS_TENSORFLOW:
        return self._build_sklearn_fallback()
    # ... TensorFlow model ...
```

The sklearn fallback for all advanced architectures (LSTM, BNN, VAE, etc.) is an `MLPClassifier` with a depth/width matching the TF architecture's complexity. Performance is somewhat lower but the API is identical.

### What You Lose Without TensorFlow

- Actual LSTM recurrence (replaced by a deep MLP)
- Monte Carlo Dropout uncertainty in BNN (replaced by deterministic MLP)
- VAE latent space and reparameterisation trick (replaced by standard MLP)
- Normalising flow exact density modelling (replaced by standard MLP)

All four architectures still produce valid CPDs; they just lose their specific architectural properties.

### Recommendation

For research and experimentation, install TensorFlow to get the full capability of all 9 architectures. For quick experiments or Google Colab (where TF may have version conflicts), the sklearn fallback works well.

```bash
# Full installation with TensorFlow
pip install deepparameters[tensorflow]

# Base installation (sklearn only)
pip install deepparameters
```
